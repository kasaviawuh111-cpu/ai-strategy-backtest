## 两个确定的缺陷

1. 公网异步 POST 受理后返回独立结果地址。旧前端一次 GET 断网、20秒超时或不支持 `AbortSignal.any` 即抛错，丢弃地址，停止查询；“后台可能仍在处理”只是提示，没有恢复行为。只凭截图不能区分该次是网络异常、超时还是浏览器兼容问题。
2. 修改已有草稿时，后端将“有历史报告”作为 `run_requested` 的前置条件。新草稿即便明确要求“按新条件重新回测”，也只返回策略。已核验这不是前端映射丢字段。

## 本地修复

- 仅对已受理的同一结果地址 GET 重试，等待1／2／4秒，最多三次；断网、GET超时、非业务临时网关错误及截断正文可恢复。绝不为了查询结果重新发模型 POST。
- 自动重试仍失败，原 Promise 与地址保留，显示“等待恢复连接”及“继续查询结果”；恢复联网或点击按钮继续原查询。收起进度也能看到按钮，按钮手机触达高度44px。
- 带明确业务原因的错误、410过期等正常结束，不能冒充网络瞬断。后台桥仍保留原600秒执行超时和临时结果保存边界；不承诺已过期或容器重建的任务可恢复。
- 取消和超时信号覆盖 fetch 与响应正文读取，兼容缺失新静态 AbortSignal API 的浏览器。重置／卸载后旧回调不覆盖新会话；后台报告分析仍与前台独立。
- 查询恢复状态优先于旧模型状态；失败不再默认标“已完成”。真实模型文本及最高160px滚动区域保留，没有补造推理内容。
- 后端去掉错误的历史报告门槛，只根据本轮经过校验的结构化执行意图继续回测。不从模型回复中的“将回测”文字猜权限，纯编辑仍不自动运行。

## 用户后续新截图：另外一个问题

“本次还没有生成可用的策略方向，请原样重试”来自服务端 `needs_clarification / idea_guidance_model_unavailable`，不是浏览器结果GET中断。选定方案绑定股票失败、绑定后的执行校验失败等都可能返回该通用分支，不能仅凭diagnostic断言模型网络故障。
