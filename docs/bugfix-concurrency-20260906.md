# 前后台任务及多客户并发验收

2026年9月6日。本次修改已随005切换到公网，真实公网并发关键场景已通过。本记录区分受控测试、真实本地API与公网验收，不以本地结果代替公网或微信真机结果。

## 原因与本次范围

004的异步请求桥把策略创建、策略澄清与报告解读共用两个活动名额，满额直接429。外层另有全站每分钟12次写入的共用额度。旧报告可能持续占用名额，影响当前策略及另一位客户。

本次复用现有异步请求桥和进度接口，不增加账号，不改模型、提示词、行情、指标计算或交易撮合规则：

| 资源 | 005新实现 |
| --- | --- |
| 前台策略创建及澄清 | 同时执行2条，最多另等待8条 |
| 后台报告解读 | 独立执行1条，最多另等待8条，不占前台名额 |
| 每个浏览器 | 每类任务最多3条未完成；每60秒最多12次写入 |
| 全站保护 | 每60秒最多60次写入，同时处理最多4个短HTTP写请求；并非4条模型任务 |
| 状态及结果 | 接受后202返回独立请求地址，查询同一地址；等待态通过原进度接口展示排队，轮到后自动执行，不重发付费POST |
| 期限与保存 | 排队加执行共600秒上限；完成结果仍最多30条、最长10分钟，重建不保证保留 |
| Python回测队列 | 没有改动。公网当前1个计算线程、2个等待名额；多人可同时提交、查看进度，不声称所有计算无限并行 |

浏览器用随机UUID作为匿名调度标识，保存在localStorage，不是登录账号或权限凭证。禁用存储时使用内存；旧客户端无标识归兼容桶。不能将此方案称为多租户鉴权或抗恶意刷量方案。保留原同源校验、总量限制以及模型真实思考文本。

## 真实本地链路

使用与公网相同的PrivatePreviewAccess和PreviewDialogueRequests，将请求转发到本地真实Skill API。没有替换模型或行情。它验证新中间件与真实本地服务的组合，不是完整云容器压力测试。

先用真实自然语言生成贵州茅台MA20策略，并实际完成原回测`run:0d7a60dbcb4b4c588fe6982ca3963366`。最终并发场景：

1. 提交原报告AI解读；1秒后，两位独立浏览器标识同时提交股票修改。
2. 实测同一时刻2条策略请求、1条报告请求正在执行，全部202受理。
3. 客户A输入“股票换成东方财富。其他条件和回测设置保持不变，按新条件重新回测。”，10.10秒返回201且ready；逐字段检查仅股票改变，买入、卖出、日期、本金、执行约束不变。
4. 客户B从独立的平安银行草稿输入“股票换成美的集团。其他条件和回测设置保持不变，按新条件重新回测。”，11.11秒返回201且ready。
5. 两位客户分别提交新回测，都达到succeeded：东方财富`run:7c497549572145ed8d5beb2af157d0ab`，美的集团`run:1245790fb4384aefbcee108a134cece5`。均244个净值点，分别54和87条执行活动。草稿ID、股票与运行结果独立。
6. 原报告102.55秒后返回200，`runId`与`sourceResultHash`精确指向原贵州茅台结果，未指向任何新股票报告；实际观察到18,797字符模型思考返回。新策略与两次回测均在原报告分析结束前完成。时间只代表本次样本，不是P95性能承诺。

原始记录在`.artifacts/b34-concurrency/final/evidence.json`，完整响应同目录；受控测试在`tests/unit/deploy/test_preview_dialogue_requests.py`。未把活动条数当成交笔数或完整回合数。

## 不隐去的失败与边界

前两轮真实探测出现两个与限流不同的失败：名称和代码直接拼写“东方财富300059.SZ”时被要求重填股票；平安银行完整MA20自然语言请求第二次返回candidate_provider_invalid_output（第一次ready）。并发入口均已正常受理，但不能因此把模型解析判定为稳定通过；保留B35单独处理。最终场景采用用户截图中的原话以及独立既有草稿，不把重试成功解释为这些语义问题已经修复。

005已发布且同版本公网核验通过：客户A实际移动尺寸UI换股、客户B独立浏览器环境API同时修改，两份新回测均在旧报告解读结束前成功；旧报告哈希保持原运行，实际思考15,801字符、滚动区160px。[公网证据](release-public-005-20260906.md)。微信真机原场景另归B30。没有进行高负载压测、持久队列改造或账号权限隔离；B30的手机查询恢复和B29的长期存储不在本次完成范围。
