# ADR-0004：成交容量、同期持有与公司行动统一使用资金账户口径

- 状态：Accepted
- 日期：2026-08-29

## 问题

日线回测若在 09:30 使用当天收盘后才能完整知道的全天成交量，会产生未来数据泄漏。把同期持有写成复权价格首尾涨跌，又会让它与扣费、受整手和成交限制的策略账户不可比。持仓跨越除权日时，若只切换复权价格而不登记分红、送转等经济权益，现金、股数、收益和回撤都会失真。

## 决策

### 1. 成交容量只使用撮合时已经可知的事实

日线开盘撮合的默认 `capacity_mode=point_in_time_volume`：使用**上一已完成交易日成交量 × 成交量参与率**作为容量代理。容量观察必须携带来源、来源交易日和 `known_at`，并同时满足：

- `known_at` 不晚于本次撮合时刻；
- 上一交易日严格早于待撮合交易日；
- 缺少合格观察时返回 `point_in_time_capacity_unknown`，不成交；
- 当日全天成交量不能作为当日开盘集合竞价的容量输入。

`capacity_mode=unlimited` 只作为高级设置中的显式研究假设。它必须进入策略版本、运行配置、RunManifest 和结果执行假设，不能由数据缺失自动触发。

### 2. 同期持有也是可成交的资金账户

“同期持有”不再使用复权价格首尾比。它与策略账户从同一初始资金出发，在首个可成交日尝试买入并持有，复用相同的：

- 不复权成交价格与后复权技术信号分工；
- 佣金、最低佣金、印花税和滑点；
- A 股按板块版本化的最低买入数量/递增单位、涨跌停、停牌、T+1 和订单有效期；
- `capacity_mode` 与成交量参与率；
- 公司行动与应收权益账本。

比较对象是两条资金账户净值曲线。若基准无法取得撮合时可知的容量、公司行动覆盖不完整或首个买单始终无法成交，运行必须明确失败或标记不可比较，不能退回价格首尾比。

### 3. 公司行动按三个阶段记账

公司行动政策 ID 为 `cn.a_share.timeline_entitlement_receivable_settlement.date_only_cash_after_close_conservative.v2`。经济条款必须来自版本化事实，不能从复权价格反推；条款须在股权登记日收盘前已验证可知。账户按以下顺序处理：

1. **登记日权益确认（entitlement）**：按登记日收盘持仓锁定应享股数，之后卖出不改变这笔权益；
2. **除权日应收（accrual）**：除权前确认现金或股份应收，估值计入应收，但现金尚不可用于买入、股份尚不可卖；
3. **派息/到账结算（settlement）**：来源只有现金派息日期而无日内到账时间时，派息日收盘后才把应收转为可用现金，最早下一交易日可使用，不假定盘中到账；股份仍按明确到账日、上市日和可卖日盘前结转持仓批次。

现金分红、送股/转增及拆并股必须保留来源、修订、可得时间和原始响应 hash。现金分红采用 `gross_research_no_withholding.v1`：按税前总额入账，明确**没有模拟个人投资者按持有期补税/扣税**，所以不是完整税后收益。账户股数始终为整数；送转计算若出现不足 1 股权益尾数且没有最终整数登记结果或可重放分配证据，直接拒绝，不默认现金补偿。配股默认使用已实现的 `decline_no_external_cash.v1`：保留拒绝认购审计，不注入外部现金、不改变账户经济状态。未来认购路径必须另设显式、版本化政策，不能修改该默认语义。

### 4. 结果证据来自不可变运行输入

fresh submission 在准备阶段按股票和区间重新采集，校验后发布内容寻址 producer snapshot；该产物是不可变审计输入，不是可变运行缓存。Worker 只能按 RunManifest 中的精确 snapshot ID/schema/checksum 本地重放，禁止走供应商采集路径，目标缺失或身份不符时 fail closed。

结果必须展示实际运行使用的数据快照 ID/checksum、策略和 Catalog hash、执行假设、引擎版本及精确 40 位 Git SHA。资金基准政策固定标识为 `funded_buy_and_hold.same_execution_ledger.v1`，公司行动/税务/配股政策也必须进入证据。严格事件 Demo 只从 `composite_snapshot` 启动，并展示秒级 `available_at`、来源、时间质量、原始记录身份和快照身份。工作区 dirty、伪造 revision 或回退到日期级事件数据都不能作为验收运行。

### 5. Session 事实与申报数量规则分开版本化

`instrument_sessions.parquet` 使用 v2 schema，保存 `minimum_buy_quantity + buy_quantity_increment`，不再用单一 `lot_size` 冒充所有板块：沪深主板/创业板为 100/100，科创板为 200/1，北交所领域规则为 100/1。买单申报必须满足对应规则；部分成交可以形成非整手整数持仓，卖出允许清掉任意整数余额。规则身份为 `cn_a.daily_market_rules.fallback.v2`。

内部 Demo 的按需真实数据链当前覆盖沪深主板、创业板和科创板。北交所只有领域数量/涨跌停规则，仍缺可证明的历史挂牌场所归属及跨源逐日停牌/reference 事实，因此完整回测必须 fail closed，不能因规则代码存在就宣称数据链可用。

## 后果

- 旧的价格首尾比“同期持有”和使用当日全天量撮合的结果不再作为验收证据；
- 严格快照必须包含公司行动覆盖证明，即使区间内动作数为 0，也不能用空文件冒充完整；
- 历史 session 使用 BaoStock `preclose/tradestatus/isST`，并逐日与 Choice 前收和交易状态精确对照；不一致直接拒绝；
- Choice 长区间交易日历按自然年有界分块采集并在发布前合并去重，每批显式设置接收超时；不分块后复权 `csd`，防止改变复权锚点；
- 100 万元只能减少最低佣金和整手造成的尺度效应，不能绕过容量、停牌、涨跌停或公司行动数据门禁；
- 研究参数更乐观时仍可重放，但界面和结果必须显式说明，不能与默认保守结果混淆。
