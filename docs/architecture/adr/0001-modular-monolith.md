# ADR-0001：采用模块化单体与独立 Worker

- 状态：Accepted
- 日期：2026-08-28

## 决策

首期采用一个代码仓、一个后端代码包、一个 H5 应用。部署时拆成 API 和 Worker 两种进程，但共享同一领域与应用代码。数据采集继续作为独立离线管线。

## 原因

- 策略编译、信号、订单、撮合、账本之间需要强一致的版本和事件顺序。
- 当前团队和负载没有证明需要微服务。
- 单体内可用自动化依赖规则保持模块边界，避免网络契约和分布式事务。

## 约束

```text
api / worker / adapters → application → domain + ports
```

`domain` 不得反向依赖入口或基础设施。未来只有数据采集、LLM 网关或 L2 Worker 在确有独立扩容/合规需求时才允许拆出。
