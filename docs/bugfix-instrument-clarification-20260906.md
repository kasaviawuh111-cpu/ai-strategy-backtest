# B27 简称换股与澄清接续修复

日期：2026-09-06。范围：只解决简称确认时机、完整名称接续和换股时保留原设置。未发布、未推送，不重开用户已验收的 B05。

## 根因及针对性修改

1. 股票名称解析原先只请求“证券简称完全等于”，简称查不到唯一精确名称时，候选信息全部丢失。现在使用既有东方财富选股 Skill 的名称包含查询，保留真实名称、代码和查询来源；唯一精确匹配直接返回，部分匹配需要用户确认，最多三个候选。没有硬编码公司名单。
2. 第一次要求重跑、第二次仅补公司名时，缺少“未完成修改”上下文。服务端现在保存澄清问题、候选及待完成重跑意图，传给真实模型；完整名称接续原修改，“先别跑／取消”等当前意图可以覆盖待完成动作。
3. 候选按钮走原草稿的澄清接口，不另起策略编译；前端仅依照服务端本轮 `runRequested` 执行。`isStrategyEdit` 区分旧策略修改与全新策略，只有前者保留已有成交费用，避免新策略继承无关费用。

错误来源区分：选股 Skill 网络失败不伪装成“名称有歧义”；只有实际拿到的名称才能作为候选。

## 最小回归与边界

- Python 定向 14 项通过：包含名称候选、精确名称优先、待完成意图、否定重跑及刷新意图边界。
- 前端定向 14 项通过：包含候选点击与输入完整名称、继续／取消执行、费用继承范围、既有失败卡片重试。类型检查、变更文件 ESLint、Ruff、差异空白检查通过。
- 单元测试使用结构化测试输入验证守卫，不算模型或真实数据证据；真实证据是上面的正式页面旅程。
- 官方安装的筛选脚本原请求及一次网络重试都返回 MCP 调用错误；未继续反复尝试。项目既有东方财富适配器通过其已有连接兼容配置完成同一 Skill 的真实查询。没有把脚本错误登记为已解决。
- 自然语言佣金／滑点修改的完整模型字段链尚未接齐（B03）；这次只保证已有费用在换股时不丢失。
- 后端重启丢失草稿／分析（B26）仍未修，不能把此次正常进程内接续视为重启恢复成功。
- 额外检查发现成交设置摘要按“本轮识别基线”比较，可能显示“默认”，但打开面板实际仍为 2／0／0；这是标签含义问题，不是费用丢失。已改为与同一份系统默认值比较，默认数值未改变；3 项摘要回归通过，当前真实页面已确认显示“已调整 3 项”。
- B19、B20、B28 未确认的设计未实施；B05 保持已关闭。
