# 手机回测反馈与模型进度展示：本地实施证据

## 状态与范围

本轮修改已在本地实施并进行定向验证，**尚未部署公网**。本文记录的是本地浏览器、离线 fixture 和本地真实数据运行证据，不代表微信真机或公网验收通过。

本轮覆盖手机审阅页提交回测后的反馈，以及公网入口与本地入口的模型进度展示一致性。首页快捷 chip 失败（B30）、条件分组与区间（B19）、完整的思考耗时设计（B20）没有在本轮解决。

## 已实施修改

| 范围 | 本轮行为 | 保持的边界 |
| --- | --- | --- |
| 公网部署入口 | `deploy/private_preview/entrypoint.py` 的 `include_model_reasoning` 改为 `True`，与本地 `create_skill_app` 一致 | 配置仍只在本地；仅接收现有供应商实际返回的 `reasoning_content`，不新增模型调用，不编造缺失文本 |
| 手机审阅页提交 | `web/src/App.tsx` 在回测请求受理后回到对话，展示运行状态；提交失败也回对话展示错误，保留股票、规则和成交参数 | 不再把运行中或失败卡留在手机审阅面板背后；不等于报告页返回按钮已修复 |
| 进度区域 | `web/src/components/ModelReasoning.tsx` 将最新实际状态短语与已收到的模型文本放入同一个 160 px 高的滚动区 | 不在滚动区外重复列状态；新内容默认跟随到底部，用户上翻后停止自动跟随 |
| 请求结束后的进度收尾 | `web/src/shared/api/client.ts` 对终态追加一次进度 GET，最多等待 1 秒 | 不重复 POST、不再次调用模型；收尾 GET 失败不影响已经返回的正文 |

公网异步包装 `PreviewDialogueRequests` 保留原请求头和请求体，进度 GET 透传；未发现它额外剥离模型文本，因此没有修改该包装。原有并发容量、取消和清理逻辑未改。

新增后端 fixture 覆盖供应商有 / 无 `reasoning_content` 两种情况：两个并发 UUID 的内容互不混合，未知 UUID 返回 404，进度响应 `Cache-Control: no-store`，最终业务 JSON 不夹带推理字段，重复查询不再次执行原请求。没有供应商文本时不生成替代文本。测试文本未进入日志。

本轮修改没有新增敏感内容日志。取消行为的保持来自未改动相关实现的核对，不应写成已完成微信后台切换或真机取消验收。
