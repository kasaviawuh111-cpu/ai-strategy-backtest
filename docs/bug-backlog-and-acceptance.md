- 本项目后续每次正式回复末尾附“待处理与验收清单”：列出全部未关闭编号、短标题、状态；详尽证据和验收口径放在本文。不只列当轮修改项。
- 编号不变。新增问题追加；合并要保留原编号指向；不悄悄删除失败项。
- “代码已修”“历史局部真实通过”“待用户验收”“已验收关闭”分开。没有最新复验时明说，不把已知旧失败当成今天刚复现。

- 不为更新清单重跑全部测试，不增加无关基础设施；修改后只测影响范围及必要真实链路。
- 每个编号附“验收场景与具体输入”，包括前置状态、可直接输入的原句或点击动作及通过表现。一次只交付当前项供用户验收，不要求用户同时重测全表。

## 状态与优先级

- **未解决**：有明确未闭环失败或需求缺口。
- **待定向确认**：有通用实现，但特定原句、分支或当前状态没有足够证据。
- **已修待验收**：有修复及对应局部真实记录，仍需用户按原操作验收。
- **预览待确认**：只有设计预览，正式页面没有实现。
- **暂缓**：用户已转向其他方案或明确留待后续；不偷偷恢复。
- **已完成**：可核实交付，保留归档。

P0 是回测失败、误执行或修改失真；P1 是主要对话、推荐、交互和分析体验；P2 是交付整理与后续能力。优先级不表示用户必须立即验收所有条目。
