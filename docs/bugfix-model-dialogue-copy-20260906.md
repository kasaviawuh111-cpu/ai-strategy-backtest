# B13：正常正文完整由模型输出

日期：2026-09-06。正式本地页面 `5184 → 8011`，真实 DeepSeek 与东方财富 Skill。未提交、推送或公开发布。本文所有时刻均为 UTC。

## 交付与范围

正常查数摘要、首次解析成功、候选选择及补充后的确认，复用已有对话模型形成一段完整正文。前端不再拿固定“已经把这句话整理成买卖规则……”覆盖或追加。模型已有的选择回复直接复用，避免为同一确认重复调用模型。

错误、数据状态和执行边界仍由实际服务状态确定；模型不可修改行情、数值、策略或执行结果。没有新增数据源、撮合引擎或无限模型循环。B13 局部已修待用户验收；B06／B12 的周期不一致仍未解决，见下方失败证据。

## 最小实现

- `compile_strategy.py` 的 ready 回复只传已通过校验的实际策略与成交设置，不改执行状态。候选选择已有模型回复时直接复用；没有有效模型回复时仍显示明确错误，不冒充生成成功。
- `dialogue_turn.py` 的股票绑定、完整新规则路径保留模型确认；待补充时不拿绑定前的回复覆盖新的问题。
- `strategy_drafts.py` 的初始 ready 接入同一回复；普通筛选、复合查数、推荐与待补股票摘要复用 response-only 模型。原始表格完整保留，模型失败不丢数据。
- 模型提示要求回应本轮、只问决定性缺项、不把聊天强行引回投资、不拼上旧问题。正常结果说明不要求用户再次输入已经明确的日期／字段。
- 返回正文仍进行既有数字、来源、能力边界检查。response-only 校验失败时在既有两次请求总预算内完整重写一次，事实输入保持原样，不将失败正文当作新证据。
- 提供方代码／名称映射通过 typed request 传递；正文使用已知代码却没有对应提供方名称时拒绝并修正。此边界用于拦截本次实际名称错配，不声称能验证一切语义事实或所有姓名排列。
- 前端保存并显示实际 `assistant_message`，当前顺序为“处理过程 → 模型回复 → 策略预览”；旧版本消息保留在各自历史中，不复制固定成功说明。
- 删除归档阶段的固定句过滤器，模型原文逐字保留。完成报告后直接编辑参数，旧回复只属于历史版本，不当作新参数的解释；未回测草稿编辑保留当前回复。此次真实报告页将本金 100 万改为 200 万后，已确认旧模型回复只有历史一份，没有自动回测；同时发现原始用户句和旧进度仍会再显示，另以定向组件回归收尾，不为这个显示改动再发一轮模型请求。

## 真实查数：修正名称，但周期仍不通过

每次都使用同一句原问题：

> 查询A股最近一个交易日成交额最高的3只股票，列出股票名称和成交额。

提供方实际返回列为 `区间成交额 2026.09.03 - 2026.09.04`，样本中际旭创（300308）350.69 亿、浪潮信息（000977）233.96 亿、长鑫科技（688825）222.87 亿。这里仅记录接口事实，不是本文件向用户推荐股票，也不是已经验证的单日排名。

1. 草稿 `a98c98c0-d628-4732-9504-11e67d69e29f`：真实数据已返回，模型正文被 `unsupplied_numeric_fact` 拒绝，表格仍显示。失败正文未保存，不能断言是某一个数字或单位转换导致。
2. 草稿 `da7401fe-75a6-45c7-acb9-3cd112f71f26`：修正后模型完整回复并说明区间，但只报代码没有用户要求的名称。不算完整回答。
3. 草稿 `0aeb0485-5d68-401d-b550-ad483743cd3a`：模型把 688825 写为“中芯集成”，与同页提供方“长鑫科技”不符。保留这个失败，增加名称／代码对应边界。
4. 草稿 `9db3c2a1-f48b-4a90-80fd-9f530941d1c9`，07:54:00.786363：三组名称代码数值与表格一致，也不再让用户重复补充日期。但首句仍称“已按最近一个交易日返回”，后句才说明是两日区间，前后含义不一致。

因此：本次真实名称修正通过；**用户原查询总体不通过**。下一步应在 B06／B12 让模型根据实际返回字段判断是否满足问题，不满足则有界补查；确实无法得到单日口径时明确说明不满足，不把区间改名为单日，也不让用户重新提出已经清楚的问题。

后续代码入口已只读定位，尚未实施：`strategy_drafts.py:_resolve_live_data_query` 的取数后／正文前；请求口径来自原始 `answer`，实际日期口径由 `mx_saas.py:_column_metadata` 保留在列名。复用既有 advisor 连接与有界补查模式，模型判断满足与否并提出修正查询，最多追加一次供应商请求。用户要全市场单日 TOP3 时必须重筛选，不能只查区间 TOP3 的单日数值就宣称全市场排名正确。
