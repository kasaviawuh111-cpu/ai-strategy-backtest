## 这次解决的混淆

此前同一组通用失败可能来自模型鉴权、余额、网络超时，或结果结构校验；部分上层把异常吞成空结果，继续要求用户补条件。现在保留传输层可验证的类型，经现有 API 错误合同返回。

| 已知证据 | 用户可区分的原因 |
| --- | --- |
| 模型 HTTP 401 / 403 | 鉴权失败 / 访问权限被拒绝 |
| 官方 DeepSeek 域名且 provider 为 DeepSeek，HTTP 402 | DeepSeek 账户余额不足 |
| 其他模型网关 HTTP 402 | 计费受限，不推断为 DeepSeek 欠费 |
| 模型 HTTP 429 / 5xx | 频率受限 / 服务端异常 |
| 实际超时 / 连接异常 | 请求超时 / 连接或传输中断 |
| 非法 JSON / 不完整流式响应 | 返回格式无效 / 响应未完整返回 |
| 东方财富授权 / 超时 / 实际 HTTP 429 / 5xx | 对应查数或选股服务的具体故障 |
| HTTP 200 内未经证实的业务 402/429 | 数据响应不可用，不套用 HTTP 状态码含义 |

402 的官方含义依据 [DeepSeek 错误码文档](https://api-docs.deepseek.com/quick_start/error_codes/)。这项映射不代表当前账户欠费；本轮随后有真实模型调用成功。没有读取余额、充值、更换 Key 或故意消耗到欠费。

## 状态与数据保护

- 编译、编辑、澄清、观点生成、模型复核及查询规划保留已分类错误，不再降成“还需要补条件”。401/402 不盲目重试。
- 查询规划抛出的错误在观点入口也继续传播；该外层曾再次吞掉原因，交叉审查后已补回归。
- 原策略、股票、日期、成交设置和待确认状态保持。错误本身不能授予新回测意图。
- 查询已取到表格、但模型核对或第二次补查失败时，保留实际表格并说明失败环节，不把已有数据删掉，也不标成核对通过。
- B15 已验证方案的确认文案失败时，仍保留选中的精确方案和既有运行意图；提示确认说明不可用，不冒充完整模型确认成功。
- 日志和 HTTP 只返回白名单原因、可验证 HTTP 状态和请求编号；测试检查原始响应、Key 哨兵不出现在响应或日志。未知旧异常保留原兼容行为，不制造细分类原因。
